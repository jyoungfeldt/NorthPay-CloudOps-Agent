# RB-S3-001: S3 Public Access — Detection and Remediation

**Runbook ID:** RB-S3-001  
**Applies to:** All NorthPay AWS accounts  
**PCI-DSS Controls:** DSS 3.4, DSS 7.2  
**Last updated:** 2026-10-01  
**Owner:** NorthPay Cloud Security Team  

---

## Problem

An Amazon S3 bucket has public access enabled, meaning unauthenticated internet users
can read (and potentially write) its contents. In a fintech environment, this is a
critical finding: a public bucket may expose customer PII, transaction records, or
cardholder data.

PCI DSS Requirement 7.2 requires that access to system components and cardholder data
is restricted to only those individuals whose job requires such access. Public S3 buckets
violate this control.

---

## Detection

Security Hub finding type: `Software and Configuration Checks/AWS Security Best Practices`  
Finding title contains: `S3 Bucket Should Prohibit Public Access`

You will also see this in AWS Config rule: `s3-bucket-public-read-prohibited`

---

## Risk

| Exposure | Impact |
|---|---|
| Public read | Customer data, transaction records accessible to anyone |
| Public write | Attacker can upload malicious content or exhaust storage |
| PCI scope | All buckets in scope for PCI DSS audit |

---

## Remediation Steps

### Automated remediation (via CloudOps Agent)
The agent can apply this fix after human approval:
```
Action: s3_block_public_access
Effect: Enables all four BlockPublicAccess flags on the bucket
```

### Manual remediation
```bash
# Block all public access
aws s3api put-public-access-block \
  --bucket <BUCKET_NAME> \
  --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# Verify
aws s3api get-public-access-block --bucket <BUCKET_NAME>
```

### If the bucket must be public (e.g., a static website)
1. Confirm with the data owner that the bucket contains no PII or cardholder data.
2. Add a bucket tag: `DataClassification=Public`
3. Create a Security Hub suppression with justification.
4. Document the exception in the risk register.

---

## Verification

After applying the fix:
```bash
aws s3api get-public-access-block --bucket <BUCKET_NAME>
# All four values should be true
```

Check Security Hub — the finding should move to `RESOLVED` within 24 hours.

---

## Escalation

If the bucket owner objects or the change cannot be made immediately:
1. Create a Jira ticket tagged `PCI-RISK`.
2. Notify the Head of Engineering and CISO within 24 hours (PCI requirement).
3. Set a remediation deadline of 7 days.
